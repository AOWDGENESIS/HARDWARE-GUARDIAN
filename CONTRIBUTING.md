# Contributing

Thanks for helping improve HARDWARE GUARDIAN.

- Open an issue before large changes and include reproducible steps.
- Never include tokens, private user data, serial numbers, or unredacted system logs.
- Keep system changes opt-in. Do not bypass UAC or silently disable security features.
- Add tests for success, failure, cancellation, permission denial, and rollback paths when relevant.
- Do not label a result as successful without a verifiable postcondition.
- Document Windows versions and prerequisites used for validation.
- Do not publish releases until builds, tests, security checks, and release evidence have passed.
